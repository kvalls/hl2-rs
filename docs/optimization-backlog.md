## Measuring an item (owner, 2026-11-22)

Before implementing or validating an item, read its `Measure` column and follow every scene and metric it names — never substitute the NPC crowd test by habit for areas it does not cover (and never try to force bit-determinism on chaotic NPC crowd fights). Pass `--item <ID>` to `.agents/skills/hl2-performance-trace/scripts/capture.py` (`headless` or `launch`) so `capture_meta.json` stamps `executable_sha256`, `args`, `backlog_item` and `backlog_measure`. Never mark an item `done` while any listed measure is unrun, and state any skipped measure explicitly as **not tested**:

- What it changes: CPU stage (`--profile` stage mean, p95, p99 bound), GPU pass time (headless
  Metal System Trace per pass), frame pacing (displayed-surface intervals, missed refreshes), hitch
  frequency and size (the slowest frames, not the mean), load time, memory peak, or allocations.
- Where it shows: run every scene in the item's `Measure` cell. If a listed scene turns out wrong for the item, update the `Measure` cell with the reason before fixing. When no scene exists yet, add one under `test-inputs/performance-research/` (or a frame-matched replay capture for fidelity).
- Which bound limits the frame there: a CPU cut in a GPU-bound scene (the static spawn at maxed
  settings) shows as render-thread wait, not frame time; say so and measure the stage itself.
- Isolating gains and noise: verify `executable_sha256` differs between A and B runs (refuse identical binaries unless running an explicit A/A control), discard a cold warm-up run, alternate builds (`A-B-B-A`, at least three runs per side), and run an A/A control on the **target scene** to establish its noise floor when deltas are small. Prefer exact work counters (draws, passes, materials, rewritten meshes) alongside timings.
